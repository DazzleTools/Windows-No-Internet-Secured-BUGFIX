# Human Test Checklist — IPv6 NCSI Diagnostic (Phase 1)

**Feature:** read-only `--diagnose-ipv6` diagnostic that classifies why Windows may mark an interface's IPv6 as "local network."
**Anticipated version:** v0.7.13 (unreleased at time of writing; tool currently 0.7.12)
**Automated coverage:** `tests/test_ipv6_ncsi_diagnostic.py` (13 tests) — classification core, `::1` regression, read-only registry spy, never-raises.

## Why this checklist exists (what the mocks DON'T cover)
The automated tests validate the *pure classification logic* with synthetic address lists, and prove the registry path is read-only. They do **not** exercise the real gatherers on machines with different IPv6 configurations, because the dev box has **no global IPv6 address** — it can only produce the `NoGlobalAddress (link-local)` verdict live. The verdicts below need real hardware:

| Verdict | Needs a machine that has… | Verified on dev box? |
|---|---|---|
| `NoGlobalAddress` (link-local) | no IPv6 beyond link-local | ✅ yes |
| `NoGlobalAddress` (ULA) | NAT66 / ULA-only (the issue #9 reporter's case) | ❌ NO |
| `Healthy` | a global IPv6 address + working IPv6 internet | ❌ NO |
| `ProbeBlocked` | a global IPv6 address but blocked/intercepted IPv6 probe | ❌ NO |
| `NoIPv6` | IPv6 disabled on all adapters | ❌ NO |

## Prerequisites
- Windows 10 or 11, Python 3.8+
- Run from the repo root
- **No admin required** (this is read-only) — confirm that claim in step 1

## Steps

### 1. Runs without admin, makes no changes
- [ ] In a **non-elevated** terminal: `python installer.py --diagnose-ipv6 --nobanner`
- [ ] It prints a report and exits 0 (no elevation prompt)
- [ ] Before/after, confirm registry is untouched:
      `Get-ItemProperty 'HKLM:\SYSTEM\CurrentControlSet\Services\NlaSvc\Parameters\Internet' | Select ActiveWebProbeHostV6`
      (value identical before and after the run)

### 2. ASCII rendering (Windows codepage)
- [ ] Run in **cmd.exe** (codepage 437): output has no garbled characters (no stray `—`, smart quotes, arrows)
- [ ] Run in **PowerShell**: same clean output
      *(Report uses `--` and plain ASCII by design.)*

### 3. Verdict matches reality — run on as many of these as you can
- [ ] **GUA + working IPv6** (e.g. native IPv6 ISP): verdict `Healthy`, probe shows `SUCCESS`, "Can this tool help? NO"
- [ ] **NAT66 / ULA-only** (issue #9 reporter's case): verdict `NoGlobalAddress`, headline says "unique-local (ULA…)", "Can this tool help? NO", router-side fix mentioned
- [ ] **GUA present but IPv6 probe blocked** (firewall-block `ipv6.msftconnecttest.com`): verdict `ProbeBlocked`, "Can this tool help? POSSIBLY"
- [ ] **IPv6 disabled on all adapters**: verdict `NoIPv6`

### 4. Address enumeration sanity
- [ ] The "IPv6 addresses by scope" list matches `netsh interface ipv6 show address` (every real address appears, classified global/ula/link-local/loopback)
- [ ] A machine with a `::`-leading address (e.g. `::1`) shows it (regression: anchored regex used to drop these)

### 5. Cross-check against Windows' own view
- [ ] Compare the verdict to `Get-NetConnectionProfile | FL Name,IPv6Connectivity` — a `Healthy` verdict should correspond to `IPv6Connectivity: Internet`; `NoGlobalAddress`/`NoIPv6` should correspond to `LocalNetwork`/`NoTraffic`

## If a verdict is WRONG
Capture and attach to the IPv6 DWP as a verbatim correction → new fixture in `tests/test_ipv6_ncsi_diagnostic.py`:
- `netsh interface ipv6 show address`
- `Get-NetConnectionProfile | FL`
- the full `--diagnose-ipv6` output

## Cleanup
None — the diagnostic is read-only and creates no files.
