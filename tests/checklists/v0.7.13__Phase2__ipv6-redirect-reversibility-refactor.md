# Human Test Checklist: IPv6 Redirect Reversibility Refactor (Phase 2 checkpoint)

**Target version:** 0.7.13 (branch `feature-ipv6`; Phase 2 WIP)
**Ships with commit:** `feat(ipv6): add reversible IPv6 NCSI redirect core (Phase 2 WIP, #9)`
**Companion automated tests:** 4 in `tests/test_ipv6_redirect_reversibility.py` (AC-O1 registry round-trip x2, AC-O2 hosts round-trip x2); plus 13 in `tests/test_ipv6_ncsi_diagnostic.py`. 20 total in the suite.

## What this is

This verifies the refactor that made the **existing uninstall/reset path** cover the IPv6 NCSI values. `backup_registry_values`, `restore_registry_from_backup`, `restore_hosts_file`, and `check_ncsi_registry` now loop a shared `NCSI_MANAGED_VALUES` set (V4 + V6), and `reset` now also clears the V6 probe values. New write functions (`update_ncsi_registry_v6`, `update_hosts_file_v6`, `configure_system_ipv6`) exist but are **not wired to any CLI yet**. The full configure -> verify -> reset reporter protocol checklist comes with the CLI/dual-stack server.

## ⚠ SAFETY — READ FIRST (do not damage this machine)

This refactor's regression surface is the **real `HKLM\...\NlaSvc\Parameters\Internet` registry, the real `hosts` file, and the real `NlaSvc` service**. The checklist is split into two zones:

- **GREEN (safe on any machine):** mocked pytest, the **read-only** diagnostic, and the **refusal** path (`configure_system_ipv6` aborts with no changes when there's no global IPv6 address). These make **zero** mutations. Run them here.
- **RED (ISOLATED-ENV-ONLY):** anything that actually applies the redirect or runs a real reset/uninstall against live HKLM/hosts. **Never run RED on the live dev box.** Run RED only in a throwaway VM/sandbox, or let the issue #9 reporter run it on their machine. Each RED row says why and how to back up first.

This dev box has **no global IPv6 address**, so `configure_system_ipv6` *refuses* anyway — but do not rely on that; treat RED rows as off-limits here regardless.

## High-Value Verification (~5 minutes, all GREEN)

### HV.1 — Automated reversibility tests pass
Validates: the backup/restore round-trip logic (the core safety guarantee).
- [ ] **Steps:** `python -m pytest tests/test_ipv6_redirect_reversibility.py -v`
- [ ] **Expected:** 4 passed (registry round-trip identical; deletes additions absent at backup; hosts add/restore; hosts idempotent).
- [ ] **Why this matters:** if these fail, the undo logic is broken — do not let anyone apply the redirect.

### HV.2 — Full suite still green (no regression in existing reset/config code)
Validates: the managed-value refactor didn't break existing V4 behavior.
- [ ] **Steps:** `python -m pytest tests/ -q`
- [ ] **Expected:** 20 passed.
- [ ] **Why this matters:** the refactor touched the live `restore_*` functions the V4 uninstall relies on.

### HV.3 — `configure_system_ipv6` REFUSES with no changes on a no-GUA box
Validates: the diagnostic-gate (the main safety interlock) and that refusal is mutation-free.
- [ ] **Steps** (non-admin is fine; same across shells):
  ```
  python -c "import system_config as s; print('result:', s.configure_system_ipv6())"
  ```
- [ ] **Expected:** logs `No global IPv6 address (GUA) found ... Aborting (no changes made).` and prints `result: False`. (On a non-admin shell it may instead refuse at the admin check — also acceptable, also no mutation.)
- [ ] **Check (proves no mutation):** registry V6 values unchanged — see HV.4.
- [ ] **Why this matters:** the tool must never touch a machine it can't help.

### HV.4 — The diagnostic is read-only (registry unchanged before/after)
Validates: `--diagnose-ipv6` makes no writes.
- [ ] **Steps** (PowerShell):
  ```powershell
  $k='HKLM:\SYSTEM\CurrentControlSet\Services\NlaSvc\Parameters\Internet'
  (Get-ItemProperty $k).ActiveWebProbeHostV6
  python installer.py --diagnose-ipv6 --nobanner | Out-Null
  (Get-ItemProperty $k).ActiveWebProbeHostV6
  ```
- [ ] **Expected:** both reads identical (`ipv6.msftconnecttest.com` on a default box). No change.
- [ ] **Why this matters:** the read-only contract is what lets the reporter run it safely.

### HV.5 — The `.reg` full-restore safety net is real
Validates: the belt-and-suspenders restore path the reversibility note relies on.
- [ ] **Steps:** Read `create_windows_defaults_reg` content in `system_config.py` and confirm it now lists the V6 defaults (`ActiveWebProbeHostV6`, `ActiveDnsProbeContentV6="fd3e:4f5a:5b81::1"`, etc.).
- [ ] **Expected:** all five V6 defaults present.
- [ ] **Why this matters:** if auto-reset ever under-restores, this file is the documented manual restore.

## Section 2: RED — ISOLATED-ENV-ONLY (do NOT run on the live dev box)

> Run these ONLY in a throwaway VM/sandbox (snapshot first) or hand them to the issue #9 reporter. They MUTATE the live registry + hosts + restart NlaSvc. Each is the work the reporter will do in the full Phase 2 protocol once the CLI ships.

### 2.1 Apply + undo round-trip on a real GUA machine — ISOLATED ONLY
- [ ] **Pre-step (mandatory):** snapshot the VM. Confirm a `.reg` backup will be written under `%LOCALAPPDATA%\NCSI_Resolver\Backups`.
- [ ] **Steps (admin, isolated):**
  ```
  python -c "import system_config as s; print(s.configure_system_ipv6())"   # applies on a GUA box
  python installer.py --diagnose-ipv6 --nobanner                            # expect Healthy if it worked
  python -c "import system_config as s; print(s.reset_configuration())"     # undo
  python installer.py --diagnose-ipv6 --nobanner                            # expect back to baseline
  ```
- [ ] **Expected:** after reset, hosts entry for `ipv6.msftconnecttest.com` is gone; V6 registry values are removed (Windows falls back to internal defaults) or restorable via the `.reg`.
- [ ] **Known behavior (not a bug):** `reset_configuration()` *deletes* the managed overrides rather than restoring them to `ipv6.msftconnecttest.com`; functional connectivity returns to Windows defaults. Byte-identical restore is via the `.reg` backup.

### 2.2 Uninstall on a V4-configured machine still clean — ISOLATED ONLY
- [ ] **Why:** the refactor made `reset` also clear V6 values even when only V4 was configured. Confirm an existing V4 install still uninstalls cleanly and the box returns to working NCSI.
- [ ] **Steps (admin, isolated):** install V4 normally, then `python installer.py --uninstall`, then confirm connectivity + that the hosts file has neither NCSI host entry.

## What the automated tests DON'T cover (why this checklist exists)

- Real `HKLM` registry read/write/delete and the actual `reg export` (.reg) round-trip
- Real `hosts` file mutation + the real `NlaSvc` restart side effects
- Whether `reset`/uninstall returns a real machine to working NCSI (RED 2.1/2.2)
- ASCII rendering of the diagnostic in cmd.exe codepage 437 vs PowerShell
- The actual configure -> "does Windows flip IPv6 to Internet" behavior (needs a real GUA box — the reporter; full protocol ships with the CLI)

## Reset / cleanup

GREEN checks mutate nothing — no cleanup needed. RED checks: restore the VM snapshot. If a RED row was ever run outside a snapshot, double-click the `.reg` backup in `%LOCALAPPDATA%\NCSI_Resolver\Backups` and run `python installer.py --uninstall`.
