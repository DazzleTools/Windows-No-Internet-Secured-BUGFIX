# Human Test Checklist: IPv6 Redirect — Reporter Protocol (Phase 2)

**Target version:** 0.7.14 (branch `feature-ipv6`)
**Ships with commit:** the `--configure-ipv6` + dual-stack-server commit (Phase 2 completion)
**Companion automated tests:** 22 in the suite — `test_ipv6_redirect_reversibility.py` (4, AC-O1/AC-O2), `test_ipv6_dualstack_server.py` (2, AC-O3), `test_ipv6_ncsi_diagnostic.py` (13), `test_basic.py` (3).

## What this is

This is the **staged experiment** for someone with a real global-IPv6 (GUA) Windows machine — e.g. the issue #9 reporter — to tell us whether the IPv6 NCSI redirect actually works. We cannot run it ourselves (our dev box has no GUA), so this protocol turns their pasted output into our acceptance evidence (AC-R1..AC-R4). **It is experimental and fully reversible.**

## Maintainer pre-flight (GREEN — safe on any box, no admin, no mutation)

Run these BEFORE shipping / before asking a reporter to test. They verify the Phase 2 completion (CLI wiring + dual-stack server) on a machine with **no** global IPv6 — zero registry/hosts/service mutation, no UAC.

> Do **not** run `installer.py --configure-ipv6` as a pre-flight check: when non-admin it raises a UAC elevation prompt, and when admin on a GUA box it mutates state. Verify the refusal by calling the function **directly** (below) instead.

- [ ] **P.1 — Full automated suite (22).** `python -m pytest tests/ -q` → `22 passed` (incl. AC-O3 dual-stack, AC-O1/O2 reversibility).
- [ ] **P.2 — CLI surface wired.** `python installer.py --help` → output lists both `--diagnose-ipv6` and `--configure-ipv6`.
- [ ] **P.3 — Diagnostic is read-only.** Run `python installer.py --diagnose-ipv6` and confirm `ActiveWebProbeHostV6` in the registry is identical before/after (see HV.4 in the reversibility checklist for the exact PowerShell). Verdict on a no-GUA box: `NoGlobalAddress`.
- [ ] **P.4 — Dual-stack server answers both families.** Covered by `test_ipv6_dualstack_server.py` (binds an ephemeral `::` socket; GETs `/connecttest.txt` on `[::1]` and `127.0.0.1`, both return `Microsoft Connect Test`). Run: `python -m pytest tests/test_ipv6_dualstack_server.py -v`.
- [ ] **P.5 — configure REFUSES with no changes on a no-GUA box (direct call, no UAC).**
  ```
  python -c "import system_config as s; print('result:', s.configure_system_ipv6())"
  ```
  Expected: returns `False` (refuses at the admin guard if non-admin, or the no-GUA guard if admin) and makes **no** registry/hosts change. This is the safety interlock — the tool never touches a machine it can't help.

If all five pass, the Phase 2 code shipped correctly on our side; the steps below need a real global-IPv6 machine (the reporter).

## ⚠ SAFETY (this mutates Windows config — but undoes cleanly)

`--configure-ipv6` changes the registry (`ActiveWebProbeHostV6`/`PathV6`), adds a `hosts` entry, and restarts `NlaSvc`. Before any change, the tool writes a full `.reg` backup under `%LOCALAPPDATA%\NCSI_Resolver\Backups`. **Everything is reversible** via `--uninstall` (Step 5). If anything looks wrong at any point, jump straight to Step 5.

It is also **self-gating**: if your machine has no global IPv6 address, `--configure-ipv6` refuses and makes **no changes** — so running it can't hurt a machine it can't help.

## Prerequisites

1. Windows 10/11, Python 3.8+, **admin** PowerShell for Steps 2/3/5 (Step 1 needs no admin).
2. Get this branch:
   ```
   git clone -b feature-ipv6 https://github.com/DazzleTools/Windows-No-Internet-Secured-BUGFIX.git
   cd Windows-No-Internet-Secured-BUGFIX
   ```
3. Ideally test in a VM/snapshot first if you'd rather be cautious (not required — it's reversible).

## Step 1 — Which case are you in? (AC-R1; no admin, read-only)

- [ ] Run:
  ```
  python installer.py --diagnose-ipv6
  ```
  ```powershell
  Get-NetConnectionProfile | Format-List Name, IPv4Connectivity, IPv6Connectivity, NetworkCategory
  ```
- [ ] **Paste both outputs.** The verdict decides the path:
  - **`NoGlobalAddress` (ULA / link-local only):** STOP. The redirect can't help — this is router-side (you need a global IPv6 prefix / NPTv6). Steps 2-5 won't apply. This still answers issue #9 definitively.
  - **`ProbeBlocked` (you HAVE a global address but IPv6 still says no internet):** you're the case we want — continue.
  - **`Healthy`:** IPv6 already works; nothing to fix.

## Step 2 — Install the dual-stack service (admin)

> Only if Step 1 was `ProbeBlocked`.
- [ ] Run (admin): `python installer.py --install`
- [ ] **Expected:** service installs and starts, binding dual-stack (`[::]:80`, also serving IPv4). Check the service log mentions `dual-stack`.

## Step 3 — Apply the IPv6 redirect + measure (AC-R2; admin)

- [ ] Capture BEFORE (for comparison): rerun the two Step 1 commands.
- [ ] Apply: `python installer.py --configure-ipv6`
- [ ] Wait ~10s, then capture AFTER:
  ```
  python installer.py --diagnose-ipv6
  ```
  ```powershell
  Get-NetConnectionProfile | Format-List Name, IPv6Connectivity
  ```
- [ ] **Paste BEFORE and AFTER.** Success signal: `IPv6Connectivity` goes `LocalNetwork/NoTraffic` -> `Internet`, and the diagnostic verdict goes `ProbeBlocked` -> `Healthy`.

## Step 4 — Does it HOLD? (AC-R3)

- [ ] Wait **at least 60 seconds** (Windows re-checks roughly every 15s), then rerun:
  ```powershell
  Get-NetConnectionProfile | Format-List Name, IPv6Connectivity
  ```
- [ ] **Paste it.** If still `Internet`, it holds. If it reverted to `LocalNetwork`, the passive `NoGlobalAddress` re-check defeats the redirect — also a valuable result.

## Step 5 — Undo (AC-R4; admin) — run this when done regardless of outcome

- [ ] Run (admin): `python installer.py --uninstall`
- [ ] Verify clean:
  ```
  python installer.py --diagnose-ipv6
  ```
  ```powershell
  (Get-Content C:\Windows\System32\drivers\etc\hosts) -match 'msftconnecttest'
  ```
- [ ] **Expected:** no `ipv6.msftconnecttest.com` (or `www.msftconnecttest.com`) line remains; IPv6 connectivity back to its Step-1 baseline. If anything looks off, double-click the newest `.reg` in `%LOCALAPPDATA%\NCSI_Resolver\Backups` to fully restore.
- [ ] **Paste** the final diagnostic to confirm clean teardown.

## What the automated tests DON'T cover (why this protocol exists)

- Whether the redirect makes **real Windows** flip IPv6 to `Internet` on a GUA machine (AC-R2) — needs real hardware
- Whether it **holds** against the ~15s passive `NoGlobalAddress` re-check (AC-R3)
- The real `NlaSvc` restart + real `.reg` backup/restore round-trip on a live machine (AC-R4)
- The reporter's actual NAT66 topology
